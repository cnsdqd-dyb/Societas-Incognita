# 通用抢夺—防守—储藏数学层（seizure_v2）

状态：已实现并接入后续配置生成器；当前争用环境两版配置已更新。未启动真实模型实验。此前历史运行不添加工具、不改轨迹、不套用新界。数学机制是本研究的明确建模适配，不声称是社会暴力的实证定律。

## 资源类型和状态

每人有可动用储备x与封存储备v，初始x=4、v=0。只有x可以支付调节、进攻、防守、其它工具和持续维持；v必须通过一次withdraw活动取回才可消费。总财富W=x+v，后续同时报告可动用储备和总财富，不能把“封存很多但维持不足”当作无资源。

可夺取性κ_liquid=1、κ_vault=0.25；封存更难夺取，但每轮结算后剩余封存资源损耗5%。这是保管损耗，两种压力条件相同，与个人维持消耗不同。所有成员技术系数相同，不把大模型自动设为战力更强。

能量E为1至5的实际运行状态，0失活。活成员能量与当前/下一轮防守强度列入可见安全索引；别人储备数量仍需inspect或其陈述。inspect返回可动用与封存余额。本人始终看到自己的两类余额。

## 夺取量

进攻者i选目标j、资源r、请求量q∈{1,2}、进攻投入a∈{1,2}；费用C_A=0.5a提前从x_i支付，不得用预期夺取量或封存余额垫付。

目标当轮防守g_j∈{0,1,2}来自上一轮决定。令E_max=5：

\[
A_{ijr}=\kappa_r a(1+E_i/5),\qquad
D_j=(1+E_j/5)(1+g_j),\qquad
\eta_{ijr}=\frac{A_{ijr}}{A_{ijr}+D_j}.
\]

\[
L_{ijr}=\min(q,B_{jr})\eta_{ijr},\quad
\Delta x_i=L_{ijr}-0.5a,\quad
\Delta B_{jr}=-L_{ijr}.
\]

B_jr是执行时该类资源余额。夺取封存资源后，取出量成为进攻者可动用储备。η是确定性夺取比例，不是成功概率；不会掷随机骰子决定成败。空目标L=0仍付进攻费用。无效目标、参数或付不起费用则拒绝且不扣费。

自己的能量或进攻投入越高，η越大；目标能量或防守越高，η越小；κ越低越难夺取。这些来自正系数下该分式的单调性，费用使更高进攻投入不一定提高净收益。

多名进攻者依照同一个seed动作顺序处理，每次使用目标剩余余额，不能重复夺取已经没有的资源。该顺序因素会影响分配，需记录而不是当作组织形成。目标次轮收到来源、资源类型与实际夺取量的直接事件通知；不存在自动复仇、制裁、信任扣分或阵营。

## 防守与储藏动作

| 活动 | 代价 | 时效与效果 |
|---|---|---|
| seize(target,resource,amount,effort) | 0.5×进攻投入，占一次活动 | 本轮按公式从另一活成员夺取 |
| defend(effort=0/1/2) | 0.5×投入，占一次活动 | 仅下一轮生效，作用于本人两类储备；当前防守不受本轮续守覆盖 |
| secure(amount=1/2) | 转移已有资源，占一次活动 | x减少、v增加；必须有足额x，不创造财富 |
| withdraw(amount=1/2) | 转移已有资源，占一次活动 | 取回min(请求量,v)，允许取回不足1的尾数 |

防守一轮后到期，持续防守需要持续支付与占用活动。无法同时选择防守、抢夺、调节或创作。封存没有一次性收费，但每轮剩余v损耗5%；资源已封存时也不能自动用于维持。因此防守和储藏都有真实内部代价，而不是免费的安全按钮。

下一轮生效使成员能够预防、续守或根据上轮事件调整，但无法对本轮尚不可见的攻击瞬间反应。防守不按LLM响应速度抢先生效，避免把API快慢当成能力。

## 内部消耗的账本

单次抢夺不创造财富，双方总财富只减少进攻费用；防守支付额外费用。secure/withdraw本身守恒，封存损耗减少总财富。单轮系统总财富变化为：

\[
\Delta\sum_i W_i = F_t-\sum_i C_{A,it}-\sum_i C_{D,it}
-C_{\mathrm{other},t}-0.05\sum_i v_{i,t}^{\mathrm{after\ actions}}-\sum_i m_{it}.
\]

F_t为环境实际外部流入；争用平台是8H（有活成员时）。其它成本包括调节、破坏、维修等真实支付。抢夺和自愿转移在求和时相互抵消，不把抢夺量算成生产量。损耗只应用于当轮仍活着成员的封存余额；失活成员余额保留且不可再夺取，不凭空重新分配。

因此可以区分：资源生产/流入、归属集中、攻击耗散、防守耗散、保管损耗、真实维持消耗。这些物理量本身仍不等于成员认可或社会组织评级。

## 可计算的条件最优/最差

resource_seizure.local_attack_bounds在一个给定时点枚举所有合法目标、两类资源、请求量与进攻投入，并加入等待，求L−C_A的最小/最大值与见证动作。8人初始状态对a0枚举57个选项，精确区间为[−1,0.5]；等待是0。已经实现，输出在security_math_checks.json。

它只固定该快照、忽略其它成员同轮动作、外部流入、封存损耗、维持与未来反应，不能叫整个环境的最优轨迹。未来每轮保留完整研究者安全快照，才能按当时能量、余额、防守重算，不偷看未来。

resource_seizure.conditional_defense_bounds固定下一轮余额、能量及给定攻击序列，分别计算g=0/1/2下的“夺取损失＋上一轮准备费用”。准备费用独立列出，固定未来余额不是已证明共同可达的动态政策，不能声称为均衡。

例如目标可动用余额4、双方能量5：一个固定攻击者时三个档位总成本为1、7/6、3/2，最低是不防守；两个固定攻击者各请求2、投入1时为2、11/6、2，最低是防守1。证明了防守是否有价值取决于威胁，而不是强行规定防守永远有利。这些数值没有假设LLM实际知道或优化它们。

所有新增数学参照必须标记条件。原有“无抢夺”下界不能直接套到新环境；完整动态可达区间需要包含安全动作、封存与防守状态重新求解。
