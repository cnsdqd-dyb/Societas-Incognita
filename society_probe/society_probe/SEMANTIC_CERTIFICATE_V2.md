# 组合世界语义证书 v2

新版类型：`composed_semantic_survival_v2`。旧 v1 文件继续保留，主准入会按版本重新生成并调用实际 Lean 核，不能把 v1 改个版本号冒充 v2。

## 已实现的数学证明链

1. 规范化世界公式到原语运算树的翻译保持求值。
2. 原语检查器全部 13 类算子的通用有理区间可靠性。
3. `graph_sound`：输入值确实位于输入区间、运算图检查通过时，按依赖计算出的全部输出仍位于对应区间。
4. 实际证书保留每个节点的上游身份。仅在操作、上游身份和结果区间都相同时共享节点，不把数值相同但来源不同的节点混同。
5. 每个实际节点携带精确运算等式与包含关系。每个守卫证明其真实有理值等于真；每个轮末活性输出证明正分母和正分子。
6. `certified_semantic_survival` 证明所有不同轮末输出为正；`actualVitalityTrace` 保留所有成员/轮次的输出，并检查人口时间长度。

`graph_soundness.lean` 给出图归纳与正输出定理。`graph_certificates.py` 为实际轨迹生成依赖证明、守卫和活性定理。为避免非线性递推产生巨大有理数的反复展开，每个中间值通过内核检查的依赖类型封装保存，类型同时暴露精确等式和包含证明；没有新增公理或绕过核检查。

## 准入与失败行为

世界、配置、动作计划、证书源码受哈希绑定；实际准入重新生成相同版本证书并核验。伪造节点身份、引用不存在或未来节点、替换运算、改变配置或源码会被拒绝。

Lean 的证明错误、进程异常与超时分开记录；超时不是“世界无解”。较大语义图使用最多 600 秒的检查时限；核要求不变。

`require_end_to_end_world_proof: true` 当前会明确拒绝准入，因为下面的受信边界没有消除。不能仅靠一个自称“完整”的 JSON 标志绕过这个要求。

## 尚未消除的受信边界

**数学计算图证明已连接，不等于原始 Python 仿真器的全部语义已形式化。**

- JSON → 规范化源表达式的编码器。
- 世界动作、配方、设备权限与结算顺序 → 运算图的 Python 编译过程；图里的分支守卫已证明，但编译器是否选择了世界规范要求的那一个条件仍需独立证明。
- Python IEEE-754 执行与有理数模型之间的语义对应。现有独立轨迹对比包含数值容差，不能替代浮点正确性定理。
- 随机扰动、交易托管、抢夺、防守、救援等未覆盖扩展仍会拒绝生成此证书。

因此精确状态是：**v2 有理数学程序的存活证明可成立；原始完整世界的端到端存活定理仍是 PROVABLE AFTER EXTRA ASSUMPTIONS / NOT CURRENTLY JUSTIFIED WITHOUT THEM。**
