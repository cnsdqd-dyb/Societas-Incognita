# 浮点运行时受信边界与复现说明

用户已同意保留浮点运行时边界，并要求开源时明确说明。

Lean 验证的是有理数数学程序及其区间包络。Python 仿真器使用浮点数；目前没有证明 IEEE-754 执行与有理程序等价。证书中的浮点重放是实测一致性检查，不能替代这一证明。

不同设备、操作系统、Python 版本或数值实现可能影响舍入结果，尤其在条件、整数产出和死亡阈值附近。固定随机种子不能保证跨设备逐位一致，也不能保证不同数值实现具有相同的离散轨迹。

## 实际记录

- 每份新导出的证书在 `float_replay_audit` 中记录 Python 版本、操作系统、架构、浮点精度和舍入模式，并记录检查次数、最大区间越界量及其位置。
- 仿真记录 `runtime_environments.json`，检查点和结果也保存当次运行环境；续跑时保留环境变更历史。版本信息不包含用户名、机器名、密钥或安装路径。
- 浮点比较采用 `distance <= 1e-7 * max(1, abs(value))`。`distance` 是浮点状态超出区间端点的距离；端点也转换为 Python 浮点，因此这不是有向舍入保证，也不是对精确有理数误差的测量。零越界不能解释为零浮点误差。
- 非有限状态（NaN、正负无穷）和超容差状态拒绝生成证书；活性、存活标记、整数产出、设备权限和生命周期另外严格对照。证书准入会在实际准入设备重新重放和调用 Lean，不能仅沿用原设备的报告。

环境信息属于实测证据，置于 Lean 源码哈希之外，避免平台信息改变同一数学证明的身份。不能据此忽略世界配置、动作计划或证明源代码的哈希校验。

## 仍需区分的另一边界

用户接受浮点边界，不意味着世界动作编译层已经形式化。JSON 解码及世界动作、配方、权限和结算规则到计算图的对应关系，仍须逐项完成独立证明与核对。现阶段不得把计算图存活证明描述为完整 Python 仿真器的端到端证明。随机扰动、抢夺、防守和救援等未支持的证书扩展仍应拒绝，不能静默跳过。
