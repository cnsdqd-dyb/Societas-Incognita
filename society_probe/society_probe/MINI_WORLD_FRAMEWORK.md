# Mini-world 框架 v3

研究主线：在无共同任务、规则未知且存在生存路径的世界中，集体知识如何形成，并通过组织方式影响群体表现。

本版本是可运行的框架和离线机制验证，不是社会行为实验结果。未启动付费模型实验。

2026-10-10 实现对齐与当前默认配置见 [代码验收说明](CODE_ALIGNMENT_20261010.md)。本轮 156 项不同检查通过，包括当前 mini-world 的 50 轮设备断点恢复与篡改审计；一项旧 open-world 50 轮检查未重跑，具体范围见报告。

后续第二步增加了 [从初始资源出发的设备可达性验证](CAPABILITY_FEASIBILITY.md)：默认四种设备在有/无压力下均有合法构造与能力使用路径，4 名成员存活到 50 轮。它是全知构造策略的 Python 回放见证，不是未知规则探索、全局最优或 Lean 证明。

第三步将上述八条路径编译成了 [Lean 核检查的组合区间约束证书](COMPOSED_LEAN_SUPPORT.md)，另验证一个同时启用六机制的 50 轮世界。该扩展不覆盖随机扰动；适配器和浮点语义对应尚未在 Lean 形式化。

数学规则决定材料获取与环境反馈，人工能力规则决定材料/设备对通信、记忆、测量、制造等接口的作用。第一批四种设备已实现，见 [人工能力规则](ARTIFICIAL_CAPABILITY_RULES.md) 中的成本、权限与生命周期边界。其他候选设备尚未实现；确定性设备路径已加入上述组合区间证书。

材料特性的默认信息规则已经接入：实际获得正数量材料后，仅向持有者披露类型特性；购买、转让等产生新持有者时同样披露。原持有者保留已学知识；别人的消息仍是带来源的陈述。材料特性披露与世界方程公开/隐藏独立，公开方程也不自动公开全部材料特性。

## 数学和结算约定

`stock` 表示液态可用能量；旧字段 `energy` 是 0–5 的活性/健康指标，不是第二份物理储能。

每种材料有能量当量 `energy_value`。全局账本满足：

\[
E_{\mathrm{initial}}+E_{\mathrm{external}}=
E_{\mathrm{retained}}+E_{\mathrm{dissipated}}.
\]

保留能量包括环境储备、材料池、所有成员（含死亡成员）的库存、液态余额、金库、生产托管、物品交易托管和游戏押注。救援只恢复活性，支付的资源计入损耗。

每轮：通信 → 同时决策 → 按固定种子顺序执行动作 → 统一处理生产试验 → 状态反馈 → 材料池耗损及部分回收 → 从有来源的环境储备再生材料池 → 材料衰减及过期退款 → 生存消耗与社会模块结算 → 账本检查 → 保存。

配方条件与基础产率使用统一的试验完成前上下文；多个配方对状态的影响合计后裁剪。采集竞争、即时材料使用和交易仍受到动作执行顺序影响，属于真实转移规则，需要在证书/比较中计入。

一个试验输入多种材料，构成有向超边。无匹配配方或条件不满足时退还输入，但支付试验操作成本；成功时消耗输入，产物受到能量当量上限约束。输出结果记录发生在材料衰减前；结算后的实际库存可能更少。

## 知识与组织测量

当前“成功生产”仅表示观察到产物，不表示掌握了规律。结构化声明必须带来源，验证状态是 `passed_scoped_tests` 或 `refuted_in_tests`，不会称为普遍真理。反事实试验在克隆世界中进行，不改变实际实验状态，不向成员反馈评分。

已记录液态及物品交易图、赠送图、能量当量分布、生产试验和通信。组织的持续分工、委托履约、决策影响及有退出选择时的行为性支持，仍需在下一轮明确操作定义后增加分析，不能由资源集中或聊天数量直接推断。

知识公告分支保留原有关系，因此可研究“使知识公开后，原结构怎样变化”。它尚不是“相同知识但没有原有关系”的完整对照。安慰消息也尚未自动匹配字符/token 数。输入文本相同不保证理解相同，需要另测应用能力。

## 证书边界

累计结算后存活量：

\[
J=\sum_{t=1}^{T}\sum_{i=1}^{N}\mathbf{1}[i\text{ 在 }t\text{ 轮结算后存活}],\qquad J\le NT.
\]

全员每轮存活的合法策略取得这个指标的上界；不代表财富、公平或文化最优，也不代表无限期生存。

早期整数 Lean 检查器覆盖：整数、无噪声、无材料衰减、单位采集与清算效率、常数材料再生/外部输入，以及非约束储备情况下的 wait/gather/liquidate 策略。现已另加确定性组合区间约束检查器，覆盖有理数生产、衰减、反馈和第一批设备路径；社会扩展、扰动与适配器形式化仍未覆盖，详见 [当前 Lean 支持范围](COMPOSED_LEAN_SUPPORT.md)。

已安装官方 Lean 4.34.1 至项目 `.tools/lean-4.34.1-windows`。受限整数控制世界的 4 个成员 × 50 轮策略已通过实际 Lean 检查，状态为 `lean_checked_restricted_projection`，累计存活量为 200；检查器也确实拒绝了故意错误的存活量声明。证明文件、配置、轨迹和检查结果在 `reports/mini_world_v2_preparation`。Python 随机产出回放只标记 `fixed_seed_trajectory_only`，不证明对全部扰动稳健。实际 Python 使用浮点，受限 Lean 模型使用整数；需要检查投影条件与转移一致性，不能声称整个仿真器已形式化。

世界接纳还需要：认证证书、可发现性与试错余量、生产互补性和压力标定、多样性检验。当前随机生成仅得到候选；一个测试策略失败不证明世界不可生存。禁止以当前筛选结果作为智能体社会实验结论。
