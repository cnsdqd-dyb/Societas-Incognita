# 组合公式编译证明（2026-10-10）

本步完成规范化表达式到基础运算树的编译证明，并将该证明嵌入新生成的组合生存证书。**没有完成整个世界模拟器的端到端正确性证明。**

## 精确命题与状态

**PROVABLE AS STATED**：对于任意值类型 `V`、基础运算解释 `s : Algebra V`、输入环境 `env : String → V` 和规范化表达式 `e`，

`evalTerm s env (lower e) = evalExpr s env e`。

`expression_compiler.lean` 中的 `compile_correct` 按表达式结构归纳证明这个命题；`repeat_correct` 按指数归纳证明重复乘法的翻译。定理不依赖某条轨迹的具体数值。

源语言覆盖有理数常量、变量、加减乘除、最小/最大、比较、逻辑、裁剪、整数幂。`gt/ge` 翻译成交换参数的 `lt/le`；`not` 翻译成 `1 - truth(x)`；裁剪翻译成 `min(hi,max(lo,x))`；幂翻译成重复乘法。

对于实际 Python 编译器产生的基础运算树 `t`，每个公式另有 Lean 命题 `t = lower e`，通过内核核验后，`checked_compilation_correct` 给出上述求值相等结论。

## 如何绑定实际代码

`expression_certificates.py` 使用符号值运行 **现有的 `Compiler.expr` 方法**，记录实际选择的基础运算及参数次序；不会另写一套 Python `gt/ge/clamp/pow` 翻译作为被检查的目标。

源 JSON 被独立规范化成 Lean 源表达式。多元加法/乘法/min/max 表达式展开为左折叠；`and/or` 是各参数先转成真假，再对结果取 min/max。证书嵌入源表达式、目标树、结构相等证明和通用语义定理实例。

`composed_certificates.export` 对世界定义内每个不同公式自动执行这项检查。实验准入重新生成并核验整份证书，因此修改公式翻译或证书源文件会使历史哈希失配，不能静默使用旧证书。

## 核验结果

- 8 条设备路径（4 人 × 50 轮，有/无压力）重新生成并通过 Lean；当前证书都包含公式编译证明。
- 六机制组合的 53 个不同公式通过结构与语义实例核验；其 4 人 × 50 轮生存证书也重新通过。
- 5 项新增测试通过：覆盖全部支持运算、27 个组合/边界示例；覆盖真实六机制公式；故意反转 `gt` 参数、替换幂与裁剪目标树均被 Lean 拒绝；不支持的 `exp` 拒绝生成。
- 没有调用付费模型 API。

综合回归最终为 **35 项通过，0 失败、0 错误**，结果与日志在 `reports/expression_lean_20261010/regression.json` 和 `regression.log`。验证期间曾遇到 Windows Lean 进程访问异常（退出码 `3221225477`，无证明诊断）；已固定双线程、64 MiB 线程栈并关闭异步 elaboration，最新整套回归通过。检查器将无诊断的非零进程退出单独标为 `lean_process_failed`，不会把它当作成功，也不会混同为数学命题被核拒绝。

输出见 `reports/expression_lean_20261010/` 和更新后的 `reports/composed_lean_20261010/`。

## 仍未证明的边界

1. **JSON 前端**：JSON → 规范化源表达式的 Python 编码器尚未形式化，世界定义哈希绑定不能替代解析器正确性证明。
2. **基础运算**：通用定理对一套任意但一致的基础运算成立；它不自行证明每个有理区间运算对真实有理数的包含可靠性。现有闭合数值约束核验继续保留，通用区间可靠性定理仍需补齐。
3. **运行时**：支付、资源池再生、配方匹配、设备权限和生命状态的世界转移展开仍由 Python 适配器负责。
4. **浮点与合法性**：IEEE-754 运行时等价性、除法接近零阈值、表达式范围守卫及裁剪上下界合法性不由编译定理证明。已有区间守卫与独立轨迹比较提供检查证据，不能称为运行时语义证明。
5. **剩余机制**：噪声鲁棒策略、交易托管、抢夺、防守和救援仍没有整套 Lean 语义覆盖。

因此本步准确状态是：**规范化组合公式的编译保持求值已证明；全世界转移的编译正确性仍待完成。**
