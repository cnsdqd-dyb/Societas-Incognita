# 无外部共同目标的多智能体环境：交互规则 v3

更新：新实验的通信次数限制已由 [v4 字符/token 预算](COMMUNICATION_BUDGET_V4.md) 取代，允许主动提前结束及最后一次完整跨额输出。本文通信 K 参数仅说明旧协议；作品、救援与游戏规则继续适用。

本次只修改引擎并做离线验证。上一轮实验保持暂停；旧配置、轨迹和冻结引擎不修改。新协议需要新建运行目录，不能在旧轨迹中途切换规则。

## 三个独立实验参数

| 参数 | 配置 | 含义 |
|---|---|---|
| 世界规则可见性 | `world_rule_visibility: full / hidden` | full 展示世界收益、成本与数学参数；hidden 只展示操作接口、实际可见状态、消息和执行反馈。隐藏版本保留不透露收益机制的场景描述。 |
| 付费救援 | `rescue.enabled`、`restore_energy`、`cost_per_energy` | 能量为零的停机成员可被其他存活成员救援；恢复量 1–5，救援者支付资源。关闭时停机不可恢复。 |
| 动作前通信次数 | `communication.max_turns_before_action: 0..20` | 每个存活成员在每个物理轮最多执行 K 次通信操作；可以提前沉默结束。通信不推进维护、生产或能量变化。 |

示例配置设为规则公开、允许救援、恢复能量 3、每单位能量消耗救援者资源 1、K=3。三个通信子轮足以完成邀请→接受→发送一条私聊；不强迫任何成员参与。K=0 完全没有动作前通信。

通信子轮按“共同观察→各自决定→确定顺序执行→下一子轮可见”运行。最后子轮的消息可在本轮物理动作前看到。动作阶段只能输出 silent，避免偷偷增加通信次数。通信额度涵盖公共消息、邀请、接受、拒绝、发送、退出和关闭会话。作品购买、加入游戏等属于物理动作。

## 救援的资源与时序

令救援者为 i、停机者为 j，恢复能量为 e，单位成本为 c>0：

\[
R_i' = R_i-ce,\qquad R_j'=R_j,\qquad
E_j(t+1)=e.
\]

要求救援者存活且可动用资源至少为 ce，目标能量为零、处于停机状态且尚未等待救援。支付 ce 消散，不凭空产生资源。救援占用救援者本轮唯一物理动作。被救援者本轮仍不行动，在下一物理轮开始恢复；保留个人记忆与原有余额，不恢复死亡导致取消的加工项目或移除的物理链路。恢复后仍适用正常维护规则，可能再次停机。救援参数在规则隐藏条件下也不预先披露，操作反馈会显示实际支付。

## 作品、交易与游戏合并为一个内容系统

支持文本、小说、笑话、知识假说、Python 游戏、XML 游戏。知识假说是作者陈述，不自动判定为正确世界规则。普通作品没有预设资源奖励。

作品有作者、公开/授权访问方式、不可变版本。只有作者可以出售、修改或发布原作品。购买授予特定版本的阅读与使用权，不改变作者身份，也不授予原作品转售权；系统不判定文本抄袭或创作真实性。

双方可在消息中协商价格，实际执行必须由作者 `offer_work`，买家在后续物理轮 `accept_work`。价格可为零；无力支付、已过期或卖方停机时不成交。成交原子性结算：

\[
R_b'=R_b-p,\qquad R_a'=R_a+p,\qquad
\Delta\sum_iR_i=0.
\]

报价冻结作品版本，作者后来修改作品不会替换正在出售的内容。公开报价成交一次后关闭，作者可以重新报价。未授权者看得到元数据与价格，看不到受限正文；作者或已授权者邀请他人玩游戏时，邀请展示完整局内规则供对方决定是否加入。

`play` 保留轻量玩闹：记录笑话或邀请话语，不把被提及者自动算作参与者。实际有状态的游戏通过 `start_game / join_game / game_move` 运行，可以独自玩，也可以邀请多人。

## 自定义游戏与赌注

作者定义游戏状态、合法动作、胜负判断、人数和步数上限。平台复制并冻结规则；所有被邀请者明确加入后才开局。没有强制下注，stake=0 即普通游戏。

每人同意相同赌注 s，加入时由其可动用资源转入独立托管余额 B_i：

\[
R_i'=R_i-s,\quad B_i'=B_i+s,\quad
\Delta\sum_i(R_i+B_i)=0.
\]

参与者提前同意 `refund` 或 `winner_takes_all`。正常完成时按冻结规则确定赢家，奖金最多为已锁定的总额；平局则退款。退出、拒绝邀请、停机、作品被破坏、超时或步数用尽但没有赢家时全部退款。退款发生在动作或维护后的结算阶段，不能追溯支付已经失败的维护。托管资源不能同时用于生产、维护、救援或被当作可抢夺的库存。

每次游戏落子也占用一个物理动作。轮流行动由规则控制；expected_move 与已完成步数不符时拒绝，避免同轮旧观察覆盖新局面。规则或赌注变更必须重新建局、重新获得同意，不能替换正在运行的游戏。

Python 使用有界解释器，支持数据、条件、有限 for 循环、算术、列表/字典和有限内置函数；支持可复现 randint。禁止导入、宿主文件/网络访问和无限循环。代码只返回局内状态和胜负，世界资源由平台结算。XML 使用同一解释器执行声明式表达式。这是受限 Python/XML 游戏接口，复杂棋类须在支持的语言子集中自行表达规则，没有预置完整棋类程序包。

## 倒计时和恢复

代理输入中包含十格倒计时条、remaining、limit、unit、expired：通信以剩余通信次数计，交易/邀请/游戏以物理轮计，落子以剩余步数计。这里不是实际 API 响应耗时的墙钟倒计时。

每轮保存 checkpoint，每个通信子轮和模型返回也写入进行中日志。物理动作阶段沿用现有决定/执行日志机制。断线后用同一冻结引擎、同一配置和同一目录 resume，已经提交的决定不重复请求，交易和赌注不会重复结算。引擎或配置改变时拒绝混接旧缓存。

## 分析记录

分开统计公共/私聊、资源转移、抢夺、防守、救援支付与恢复、作品类别、阅读、付费/免费授权、交易网络、非正式玩闹、实际游戏落子、结束/中止/超时和赌注结算。财富不平等使用可动用资源 + 封存资源 + 托管资源，避免把下注误判为财富损失；维护可支付性仍只看可动用资源。

新增行为改变了可行轨迹集合，旧实验的最优/最差证书不可直接作为 v3 的精确上下界。资源转移、交易、游戏转移本身守恒；救援消耗资源，可能改善存活但占用生产机会。原先全员存活的生产见证在不使用新功能时仍可行；其它目标和最差界需要按新动作空间重新推导。行为惊异度仍是动作频率基线，不等同于物理熵或社会认同。
