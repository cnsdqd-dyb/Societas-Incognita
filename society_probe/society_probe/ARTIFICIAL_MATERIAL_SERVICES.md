# 高级材料的可执行功能

本轮实现 24 类附加功能，保留原有数学状态作用。默认世界由种子选取 6 类，再生成材料要求；不是每个世界都包含全部功能。谁在可用库存中首次凑齐要求，谁私下知道作用并获得使用接口。获知不会自动使用，必须选择确认或取消。知识可通过原有通信传递，使用权限仍须本人发现且持有所需材料。

这些功能是面向智能体需求的人造环境设定。物品的复杂生产路径不意味着必然值得生产；生产升级还受输入能量、世界条件和容量限制。下面是当前生成器的默认参数，不是经验最优参数。

| 功能 | 实际作用 | 目标与叠加 |
|---|---|---|
| 作品容量 | 指定作品文本容量 ×2 | 作者自己的作品，包括小说、笑话、Python/XML 游戏；可叠加，上限 100,000 字符 |
| 记录容量 | 私人记录额度 +1,000 | 自己；可叠加，沿用记录读写接口 |
| 通信额度 | +500 个额度单位，持续 3 轮 | 自己或已加入的开放会话；会话为共享额度，使用会扣减，不能每个成员重复领取 |
| 通信范围 | 每次邀请上限 +2 人 | 自己；受群体人数限制，不自动发送或接受邀请 |
| 设备范围 | 最大服务人数 +2 | 自有设备；上限 64，供能成本继续按原规则计算 |
| 测量精度 | 测量误差 ×0.75 | 自有设备；可叠加，不直接给出规律 |
| 生产诊断 | 每次加工反馈增加 1 个状态量 | 加工台；优先测量隐藏状态，提供数值而非方程，最多 64 个诊断项 |
| 生产效率 | 产率因子 ×1.15 | 加工台；总因子上限 4，产出仍受反应能量预算限制 |
| 切换加速 | 加工模式切换等待 −1 轮 | 加工台；最低 0 轮 |
| 储存保护 | 容器中的物品衰减率 ×0.85 | 自有容器；可叠加，原本零衰减的物品仍为零 |
| 放能能力 | 单次物品放能上限 +1 | 自己；不改变物品能量密度，仍受数量上限限制 |
| 材料救援 | 0 活力成员下一轮恢复为 5 活力 | 已宕机、无待执行救援的成员；不返还资源、取消的加工任务或关系 |
| 容器加固 | 护甲 +1 | 自有容器；最多 100，降低抢夺和腐蚀效果 |
| 成员防护 | 防护 +1，持续 3 轮 | 自己；降低攻击和抢夺，不能彻底免疫 |
| 报价延期 | 有效期 +3 轮 | 自己的有效物品或作品报价；可叠加，不修改成交条件 |
| 设备腐蚀 | 完整度 −0.25 | 他人设备；最低 0，实际能力随完整度下降 |
| 设备维修 | 完整度 +0.25 | 自有设备；最高 1 |
| 设备干扰 | 有效能力 ×0.5，持续 3 轮 | 他人设备；与完整度相乘 |
| 资源污染 | 再生和采集效率 ×0.5，持续 5 轮 | 资源池；可叠加，因子最低 0.01 |
| 资源净化 | 污染因子 ×2，最多恢复到 1 | 资源池；恢复到 1 时移除污染 |
| 加工台破坏 | 暂停加工服务 | 加工台；使用轮及后续 2 轮受阻，队列按原有退化规则处理 |
| 成员攻击 | 最多损失 2 活力、1 液态能量 | 其他存活成员；防护削弱效果，可造成宕机 |
| 大范围毁伤 | 最多损失 3 活力、2 液态能量，并破坏公共环境 | 包括施用者在内的所有存活成员；污染资源池、暂时关闭加工台、损伤设备及容器库存 |
| 容器腐蚀 | 损失库存的 15% | 他人容器；护甲降低损失，损失进入能量耗散账本 |

通信额度的单位沿用世界配置的字符/token 计量；额度为 0 时不会通过材料绕过通信禁用。到达上限前最后一次完整输出仍按原规则保留。参与者可以主动结束，无须用完额度。临时效果记录到期轮；实体动作取得的效果通常从下一轮通信阶段开始可用。生产、防护等使用当轮即生效，随后经过参数指定的轮数。

普通功能消耗 1 单位液态能量，以及种子指定的 1–2 种高级材料、每种 1 单位。攻击和加工台破坏消耗 D×1、S×1、液态能量×3；救援消耗 D×1、S×1、液态能量×5；大范围毁伤消耗 D×2、S×3、液态能量×6。材料要求全部消耗，现阶段不做永久免费被动加成。救援恢复的是活力，**不会赠送 5 单位可交易能量**。

作品扩容改变实际创作、修订、读取及游戏源代码容量。已有授权买家可以读到扩容后的作品；扩容不允许非作者出售作品。游戏仍由有界解释器执行，不运行任意宿主 Python 代码，计算步数和结构约束仍有效。

每人初始有一个容量 64 单位的容器。`store_item` 存入自己的材料，`withdraw_item` 取回，包括衰减后的小数余量；`seize_storage` 尝试抢夺他人容器库存。一次操作占一个实体动作。抢夺先付 `0.5 × effort` 液态能量，effort 为 1 或 2；夺取比例取决于材料可接近性、双方活力、护甲、防护和主动防守。转移不产生能量，费用和腐蚀计入耗散；容器内材料也纳入总能量账本。

功能升级不会自动增加储量或制造物理能量。活力是独立的成员状态，不计入可转换物品的物理能量总额；活力救援须另行支付资源。生产效率改善只可能提高利用率，触及能量预算后继续升级可能没有收益。

## 验证与边界

运行 `python validate_functional_services.py` 执行离线回归，结果保存在 `reports/functional_services_20261010/acceptance.json`。覆盖真实状态作用、费用、叠加、到期、私有解锁、目标限制、共享额度扣减、作品与游戏扩容、能量账本及 5 轮强制中断恢复。这些是脚本测试，不是智能体发现能力或社会演化结果。

`python prepare_functional_world.py` 生成默认种子配置；`--all-functions` 生成全功能验证配置。两者均只写配置，**不会启动模型**。已准备的配置为 4 成员、50 轮、有压力，普通救援关闭、材料救援由种子决定；当前默认种子 2 的六类功能不含救援。全功能配置用于动作覆盖，不是已筛选的存活实验世界。

原有有界数学状态组合已有 Lean 检查；本表附加功能尚未完整形式化，证书编译遇到其确认动作会明确拒绝。完整新配置标为未认证，不能用旧证书替代验证。Python/浮点受信边界也继续保留。

checkpoint 包含功能状态与私有发现；当前验证了脚本中断恢复一致性。旧的仅实体动作审计器不能完整重建共享通信额度的消耗，含会话功能的复现实验应保留完整通信记录及模型输出，并使用完整引擎回放；本轮未声明所有新功能的完整轨迹回放已经验收。

## 真实模型小测试

另用 `prepare_functional_pilot.py` 准备自然库存的 4 成员 × 10 轮、GPT-6.1-sol/low 隐藏规则压力世界，再由 `run_functional_pilot.py` 运行。普通正式入口仍要求 Lean 证书；此诊断入口明确标为未认证，只允许指定原生后端、最多 4 人/10 轮/200 调用，并在执行前重放配置匹配、哈希检查的全员存活策略。运行时见证不是形式证明。

测试完成后 4/4 存活，40 次实体动作中采集 18 次、变现 16 次、查看 4 次、测量尝试 2 次。没有加工、作品、组合解锁或组合使用。完整记录的离线回放通过，只忽略独立摘要日志完成顺序；这没有覆盖尚未被真实模型使用的新功能。具体分析见 [真实小测试摘要](reports/functional_services_20261010/real_pilot_summary.md)。
